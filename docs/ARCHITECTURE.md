# 아키텍처

이 문서는 ELF VR의 소프트웨어와 하드웨어 구조를 정리합니다. Phase 0(PC 유선 연결)을 중심으로 설명하며, Phase 1(단독 실행)과 Phase 2(6DoF)는 확장 방향으로 표시합니다.

## 1. 구성 요소

| 계층 | 구성 | 역할 |
|------|------|------|
| OS | Armbian 또는 Debian (Linux) | 기본 운영체제 |
| 런타임 | Monado (OpenXR 런타임) | OpenXR 앱에 헤드 포즈와 디스플레이 제공 |
| 출력 | DRM lease (직접 출력) | Monado가 패널을 직접 점유해 컴포지터 지연 최소화 |
| 센서 | BNO085 / ICM-42688 IMU | 헤드 방향(쿼터니언) 측정 |
| 디스플레이 | 1440p LCD + HDMI-to-MIPI 보드 | 좌우 눈 영상 출력 |

## 2. 동작 모드

### 2.1 유선 모드 (Phase 0, 기본)

PC에 USB로 연결하면 헤드셋이 두 가지 장치로 인식됩니다.

- **디스플레이:** HDMI(또는 USB-C DP Alt Mode)로 연결된 모니터처럼 보입니다. PC의 Monado 또는 SteamVR 호환 드라이버가 이 디스플레이를 직접 제어합니다.
- **IMU:** USB HID 장치로 쿼터니언 스트림을 전송합니다. PC 측에서 OpenHMD 또는 Monado의 드라이버가 이를 읽어 헤드 포즈로 변환합니다.

```
 PC (Linux / Windows)                         헤드셋 (ELF VR)
┌──────────────────────────────┐            ┌───────────────────────────┐
│ OpenXR 앱 (게임/뷰어)         │            │                           │
│        │                     │            │  ┌─────────────────────┐  │
│ Monado / OpenHMD             │  HDMI/DP   │  │ 1440p LCD 패널      │  │
│  - 포즈 융합                  │ ─────────▶ │  │ (+ HDMI-to-MIPI)    │  │
│  - 렌더 타깃 → 디스플레이     │            │  └─────────────────────┘  │
│        ▲                     │            │                           │
│        │ USB HID (쿼터니언)   │ ◀───────── │  ┌─────────────────────┐  │
│        └─────────────────────┼            │  │ IMU (BNO085 등)      │  │
└──────────────────────────────┘            │  └─────────────────────┘  │
                                            └───────────────────────────┘
```

### 2.2 단독 실행 모드 (Phase 1)

헤드셋 내부의 RK3588 SBC가 Monado를 직접 실행합니다. 패널은 SBC의 디스플레이 출력(MIPI DSI 또는 HDMI)에 직접 연결되며, IMU는 SBC의 I2C 또는 USB에 연결됩니다.

```
┌─────────────────────────── 헤드셋 내부 ───────────────────────────┐
│                                                                   │
│   ┌──────────────────────── RK3588 SBC ─────────────────────┐    │
│   │  Armbian (Linux)                                         │    │
│   │   ├─ OpenXR 앱                                           │    │
│   │   ├─ Monado (DRM lease → 패널 직접 출력)                 │    │
│   │   └─ IMU 드라이버 (I2C / SHTP)                           │    │
│   └────────┬─────────────────────────────┬──────────────────┘    │
│            │ HDMI / DSI                  │ I2C                    │
│   ┌────────▼──────────┐        ┌─────────▼─────────┐              │
│   │ 1440p LCD 패널    │        │ IMU (BNO085)      │              │
│   └───────────────────┘        └───────────────────┘              │
│                                                                   │
│   배터리 (18650 x2-3) ─ USB-PD 보드 ─▶ SBC                        │
└───────────────────────────────────────────────────────────────────┘
```

### 2.3 무선 스트리밍 (미정)

ALVR 방식처럼 PC에서 렌더링한 영상을 무선으로 헤드셋에 보내는 방식입니다.

> **검증 필요:** ALVR의 Linux 클라이언트 지원 여부를 확인해야 합니다. 현재 ALVR 클라이언트는 주로 Android 기반이며, Linux 측 클라이언트(디코더 및 OpenXR 연동) 지원 범위는 아직 확인되지 않았습니다. 확인 전까지 이 모드는 구현 범위에 포함하지 않습니다.

## 3. 데이터 흐름 (유선 모드)

1. IMU가 센서 융합된 쿼터니언을 약 500Hz 이상으로 출력합니다.
2. PC의 드라이버가 HID 리포트를 읽고, 예측(prediction) 보정 후 Monado에 포즈를 전달합니다.
3. OpenXR 앱이 해당 포즈로 두 눈 영상을 렌더링합니다.
4. Monado가 왜곡 보정(렌즈 특성 반영) 후 DRM lease를 통해 패널로 출력합니다.

지연(motion-to-photon) 목표와 측정 방법은 [VERIFICATION.md](VERIFICATION.md)에 정리되어 있습니다.

## 5. 미결정 사항

- IMU 최종 선택: BNO085(온보드 센서 퓨전) 대 ICM-42688(원시 데이터, 외부 융합 필요)
- 패널 인터페이스: 패널에 따라 MIPI DSI 또는 eDP / HDMI 중 하나로 확정
- Phase 1 SBC 확정 및 Armbian 이미지 지원 확인
